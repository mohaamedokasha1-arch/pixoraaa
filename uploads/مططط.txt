MISSION
Build a professional, fully functional, production-ready image-processing tools platform using Next.js, TypeScript, React, Tailwind CSS, and shadcn/ui. The platform must feel like a real commercial SaaS product — not a student project, not a template, not a demo. Every tool must actually work. Every button must do something real. No fake functionality. No placeholder processing. No simulated results.

TECH STACK — MANDATORY
Framework: Next.js 14+ (App Router)
Language: TypeScript (strict mode)
Styling: Tailwind CSS
UI Components: shadcn/ui
Image Processing: Browser-native APIs (Canvas API, File API, Blob API, OffscreenCanvas)
Performance: Web Workers for CPU-intensive operations
PDF Generation: pdf-lib or jsPDF (client-side only)
State Management: React Context + hooks (no Redux unless genuinely necessary)
Internationalization: next-intl or next-i18next
SEO: Next.js Metadata API
No external image-processing APIs
No paid AI APIs
No server-side image uploads to third-party services
All 20 tools must process images entirely inside the user's browser using client-side JavaScript. If any feature technically cannot be implemented client-side, you must explicitly document the limitation and propose the minimal server-side solution before implementing it. The default is always client-side.

PHASE 9 — ALL 20 TOOLS: DETAILED IMPLEMENTATION REQUIREMENTS
Implement every tool to production quality. Use the Canvas API, OffscreenCanvas, Blob, FileReader, and Web Workers as needed.

Output: same format as input

Interactive crop interface using Canvas or a lightweight client-side crop library (react-image-crop — pure client-side, no API)

Output: cropped image in same format

PHASE 16 — SECURITY
File Validation (Defense in Depth):
Validate MIME type from file.type
Validate file extension
Validate file signature (magic bytes) by reading the first bytes of the file — do not trust file.type alone
Validate file size before processing
Reject any file that fails validation with a clear error message
Never pass unsanitized file names to the DOM or download trigger
Input Sanitization:
All text inputs (watermark text, filenames) must be sanitized before being rendered to Canvas or DOM
No innerHTML with user-provided content
Use textContent or Canvas fillText for user text
Download Safety:
Use URL.createObjectURL + programmatic <a> click for downloads
Set safe, sanitized filenames on downloads
Do not use data: URLs for large files
Content Security Policy:
Configure CSP headers in next.config.js
Allow necessary sources only
script-src: 'self' (extend carefully if analytics added)
img-src: 'self' blob: data: (needed for canvas blob previews)
Environment:
No secrets in client-side code
All environment variables that are truly client-safe are prefixed NEXT_PUBLIC_
Sensitive future keys (if any) must be server-side only
